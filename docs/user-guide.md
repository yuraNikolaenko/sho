# Shozilla — інструкція користувача

## Що це

Десктопна програма для Windows, що швидко знаходить документи з заданим текстом у вибраних папках (на одному або кількох дисках). Підходить для пошуку прізвищ, цитат, ідентифікаторів, фрагментів коду тощо в архівах документів, а також для попереднього перегляду знайдених DOCX прямо у вікні без відкривання Word.

## Підтримувані формати

| Категорія           | Розширення                                                                         |
|---------------------|------------------------------------------------------------------------------------|
| Звичайний текст     | `.txt .md .csv .tsv .log .xml .json .yaml .yml .ini .cfg .conf .properties .env` |
| Вихідний код        | `.cs .js .ts .py .rb .go .rs .java .kt .c .cpp .h .hpp .sql .sh .ps1 .bat .cmd`  |
| Веб                 | `.html .htm .xhtml .css .scss .less`                                              |
| Документи           | `.pdf .docx .xlsx .pptx .doc .xls .rtf .tex`                                      |

> **Не підтримуються:** скановані PDF (без OCR), архіви, файли під паролем, презентації PowerPoint 97–2003 (`.ppt`).
>
> **Особливості legacy-форматів:**
> - `.xls` — повна підтримка через NPOI (HSSF): значення клітинок, формули (cached-результат), числа, рядки.
> - `.doc` — текст витягується евристикою з OLE-стріму `WordDocument` (UTF‑16 LE runs). Збігаються всі реальні слова документа; у тексті можуть зустрічатись поодинокі обривки метаданих, які ігноруються пошуком (вони не псують результати, лише трохи "забруднюють" сніпети).

Кодування detected автоматично: UTF‑8 (з/без BOM), UTF‑16, CP1251, KOI8‑U. Не потрібно вказувати вручну.

## Перший запуск

1. Запусти `Shozilla.exe` (або `dotnet run --project src\Sho.App\Sho.App.csproj`).
2. Натисни **Choose folders…** у верхній частині вікна.
3. У дереві з чекбоксами розкрий потрібний диск, познач одну або кілька папок → **OK**.
4. Введи запит у полі **Find** і натисни Enter.

## Вибір папок (multi-folder picker)

Натискання **Choose folders…** відкриває діалог із деревом усієї файлової системи: всі диски (`C:\`, `D:\`, мережеві) показані як корені.

- Кожна папка має чекбокс — постав галочки на потрібних.
- Можеш позначити папки **на різних дисках** одночасно.
- Якщо позначити батьківську папку, всі піддиректорії автоматично будуть включені в пошук — позначати їх окремо не треба. Якщо випадково позначиш і батька, і дитину, дитина буде проігнорована (дедуп при OK).
- При повторному відкритті діалогу — раніше позначені гілки автоматично розкриті, інші згорнуті.
- **Зняти всі** — швидко зняти всі галочки.
- **OK** застосовує вибір; **Скасувати** залишає старий.

Зверху лейбл `Folders:` показує підсумок — `"Documents (C:\Users\…)"` для однієї папки або `"3 folders"` для кількох.

## Два режими пошуку

Чекбокс **Use index** перемикає режим:

- **Use index ON** (за замовчуванням, **рекомендується**) — пошук іде по заздалегідь побудованому Lucene-індексу. Швидкість мілісекунди, але треба один раз побудувати індекс.
- **Use index OFF** — кожне натискання **Search** перебирає всі файли у вибраних папках. Не потребує підготовки, але повільне для великих корпусів.

Стан індексу видно в **правій частині рядка стану** внизу вікна:
- `Index · 2025-04-30 14:32 · 12,453 files` — індекс побудовано, дата та кількість.
- `Index · not built` — треба натиснути Build.
- `No folders selected` — немає вибраних папок.

## Сценарій з індексом

1. Натисни **Build index**. Прогрес-бар угорі рядка стану та текст ліворуч (`Indexing 1234/5678 (21.7%) · 4.2 f/s · ETA 12m34s · big.pdf (45s on this file)`) показують, що йде. Якщо файл великий і обробляється довго, лічильник `(45s on this file)` росте — програма не зависла, просто тривалий PDF.
2. Дочекайся повідомлення `Indexed`.
3. Введи запит у поле **Find**. Натисни Enter або кнопку **Search**.
4. Результати:
   - **Files (matches)** ліворуч — файли, відсортовані за датою модифікації за зростанням. Колонки: іконка (за розширенням), Файл, Збігів, Шлях, Дата.
   - **Lines (context)** праворуч зверху — кожен рядок документа з контекстом ±80 символів навколо збігу.
   - **DOCX preview** праворуч знизу (якщо вибраний рядок належить `.docx`) — повний рендер документа з підсвічуванням збігів і авто-скролом до першого.
5. Клік на файлі ліворуч → рядки з цього файлу в правій таблиці стають **жирними** (інші лишаються видимими).
6. **Подвійний клік** на рядку відкриває документ у програмі, призначеній для його розширення (Word для `.docx`, переглядач PDF для `.pdf` тощо).

## Сценарій без індексу (швидкий разовий пошук)

1. Зніми чекбокс **Use index**.
2. Введи запит → **Search**. Програма проходить по всіх файлах вибраних папок паралельно (стільки потоків, скільки CPU).
3. Результати такі ж, як у режимі з індексом.

> Якщо текст файлу більший за 64 МБ, читається тільки перші 64 МБ (захист від log-файлів-гігантів).

## Опції пошуку

- **Match case** — увімкнути чутливість до регістру.
- **Whole word** — шукати тільки цілі слова (не як підстроку).

## Синтаксис запиту (тільки для індексного режиму)

Якщо в запиті є хоч один з операторів — `+ - " ( ) * ? ~ ^ : \ [ ] { }` або слова `AND`/`OR`/`NOT` — спрацьовує **Lucene-синтаксис**:

| Запит                                    | Результат                                           |
|-------------------------------------------|----------------------------------------------------|
| `Ніколаенко`                              | substring (як було) ✅                              |
| `Юрій Вікторович`                         | фраза з двох слів у заданому порядку ✅              |
| `"Юрій Вікторович"`                       | те саме, але через QueryParser                     |
| `"Ніколаенк"`                             | substring `*ніколаенк*` (пост-обробка обертає)     |
| `Юрій AND Вікторович`                     | обидва слова в документі (порядок неважливий) |
| `Юрій OR Maria`                           | хоч одне з двох слів                                |
| `Ніколаенко AND NOT тест`                 | `Ніколаенко` є, але `тест` нема                     |
| `+обов'язкове -виключене`                 | `+` обов'язкове, `-` виключити                       |
| `назв*`                                   | префіксний wildcard (`назва`, `назвою`, …)         |
| `назвою~2`                                | fuzzy: до 2 правок (одруки)                         |
| `ext:pdf AND content:Ніколаенко`          | поля: тільки PDF з ім'ям                            |

Brute-force режим завжди шукає буквально (нема Lucene-індексу — нема query parser).

## Історія пошуку

Поле **Find** має випадаючий список (стрілка справа) з останніми **50 запитами** з попередніх сесій. Клік на запит у списку → текст підставляється; натискаєш Enter → пошук. Дублікати не зберігаються; найновіший запит — зверху.

## DOCX preview

Якщо у Lines клікнути рядок з `.docx`-файлу, у правій нижній панелі з'явиться рендер документа через WebView2:
- Збіги обведені жовтим маркером (`<mark>`).
- Прев'ю автоматично прокручено до першого збігу.
- Cmd/Ctrl + scroll — масштабування. Ctrl + F всередині панелі — рідний пошук Edge.

Перемикач **Preview** (кнопка з іконкою ока у toolbar) приховує/показує панель. Стан зберігається в `settings.json`.

Для не-DOCX файлів панель показує `Preview is available only for .docx files.`.

## Тема та мова інтерфейсу

У правій частині панелі налаштувань (сама права секція):
- **Theme** — перемикач Dark / Light (іконка місяця/сонця).
- **🌐 UA / EN** — перемикач мови.
- **Preview** — toggle для DOCX-панелі.

Усі налаштування зберігаються в `%LOCALAPPDATA%\sho\settings.json` і відновлюються при наступному запуску.

## Прогрес індексації

Під час `Build index`/`Search` у нижньому статус-барі видно:
- стадію (`Scanning folders` / `Indexing` / `Committing index`),
- лічильник `1234/5678 (21.7%)`,
- швидкість `4.2 f/s`,
- ETA: `12m34s`,
- ім'я поточного файлу + `(45s on this file)` якщо обробка одного файлу > 2 с.

Якщо bar довго стоїть на одному файлі (велике PDF / DOC) — це нормально; лічильник `on this file` росте кожні 0.5 с, тож ти бачиш, що програма жива.

## Контекстне меню (правий клік на результаті)

- **Open** — відкрити документ.
- **Reveal in Explorer** — показати файл у Провіднику.
- **Copy path** (тільки в Files) — скопіювати повний шлях.

## Обмеження та FAQ

- **Чому в режимі з індексом не знаходить нове слово?** Індекс — це snapshot. Перебудуй (**Build index**) після того, як у папках з'явились нові файли. Кнопка `Build index` завжди робить full-recreate (немає інкрементального оновлення в v1).
- **Де зберігається індекс?** `%LOCALAPPDATA%\sho\indexes\<hash-набору-папок>\`. Хеш залежить від набору вибраних папок — інакший набір → інший індекс. `meta.json` всередині зберігає дату збірки і кількість документів.
- **Коли мій DOCX-прев'ю порожнє/червоне повідомлення?** Якщо WebView2 Runtime відсутній (типово на Win11 встановлений). На Win10 інсталюй з [microsoft.com/edge/webview2](https://developer.microsoft.com/microsoft-edge/webview2/).
- **Скільки можу шукати по великій папці?** Перевірено на ~50k документів. Індексація зазвичай 1–10 хв (залежить від розмірів PDF/DOCX). Сам пошук — мілісекунди.
- **Чи можна перервати пошук/індексацію?** Так, кнопкою **Cancel**. Lucene-індекс лишиться частковим — наступний `Build index` створить чистий.
- **Українська/російська морфологія?** У v1 пошук — за підстрокою без морфології. `Ніколаенко` не знайде `Ніколаенка` поза substring-семантикою. Lucene QueryParser-синтаксис `Ніколаєн*` як wildcard допомагає.
